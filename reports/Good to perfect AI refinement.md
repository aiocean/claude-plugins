# Perfect means a verified fixed point

A skill can push finished work toward its best achievable form only if it defines "perfect" as a **verified fixed point**: no change survives independent verification against an exemplar-derived, versioned, rising bar, inside a pass cap, with the leftovers listed. The evidence cannot support an absolute claim of perfection, because non-reasoning judges sit near chance on hard pairs (GPT-4o scored 50.86 against a 50 baseline; [JudgeBench](https://arxiv.org/html/2410.12784); HIGH), human criteria drift as people see outputs ([Shankar et al.](https://arxiv.org/html/2404.12272); HIGH, n=9), and no study measures judge accuracy among already-good subjective outputs (gap in the notes). It does support a design that inverts the earlier defect-catching one. The finished artifact becomes an **incumbent** that stays unless a challenger beats it. The first move is deletion, because LLMs add more than humans and the word "improve" pushes GPT-4 further toward adding ([Uhler et al.](https://arxiv.org/abs/2404.16692); HIGH, GPT-4 only). A change is accepted through objective checks first and a blinded, order-swapped, length-normalized, multi-judge comparison second, and **a tie keeps the incumbent, which is a design choice and not a cited result**. The bar rises by contrast with exemplars chosen outside the draft but rests on a frozen core copied from the user's request. The run ends at two consecutive empty cycles or after three cycles, whichever comes first, and reports what it could not verify. The repo rule "There is no 'perfect' code, only *better* code" (`plugins/aio-code-review/skills/aio-code-review/SKILL.md:54`) governs approving a change and does not conflict, because this pass runs afterward and asks a different question. The honest expectation is that on strong artifacts the commonest result is a small verified deletion set or no change plus a leftover list; the evidence for value is thinnest exactly where the model already does the task well (inference from the [Anthropic harness post](https://www.anthropic.com/engineering/harness-design-long-running-apps); MEDIUM), so the first deliverable is a RED test with a no-op control that can end the project. The earlier report's bar definition (a), pass structure (b) and stopping rules (d) are superseded; its independence levels (c), trigger evidence (e), overlap boundaries (f) and RED mechanics (g) stand with the amendments below.

## Three earlier design sections are superseded and four survive amended

The earlier report designed a defect-catching skill. It read "perfectize" as "raise the bar and stop at materiality", built a closed 3-7 item bar from the user's words, ran an independent critique, fixed confirmed findings behind a regression gate, and stopped at "bar met", one clean pass, or three passes. The user has since defined the target as taking masterpieces from good to perfect. That changes the starting point (work that already passes its own checks) and the question (does any improvement remain that survives verification?). Where the new notes and the earlier report disagree, the new notes win. Table 1 lists each reversal and Table 2 states what stands.

## "Perfect" cannot be certified, so the definition must be a fixed point

The user's word asks for something no source can verify. Google's reviewer standard says there is "no such thing as 'perfect' code" ([Google eng-practices](https://google.github.io/eng-practices/review/reviewer/standard.html); HIGH per the earlier report), and the repo repeats it at `aio-code-review/SKILL.md:54`. Both new notes resolve the clash the same way: that sentence governs **approving a change** (merge once it definitely improves code health), whereas a good-to-perfect pass runs afterward on work that is already approved or already good and asks whether any improvement remains that survives verification (craft note section 5, LLM note section 6; MEDIUM, design reading). The two coexist only if "perfect" is relative and finite. A high bar is not the hazard. A meta-analysis of 28 samples and 77 effect sizes (N=9,560) found perfectionistic strivings correlate with performance, while perfectionistic concerns correlate with hours worked but not with performance ([Bellam and Curran 2025](https://researchonline.lse.ac.uk/id/eprint/128910/); HIGH, abstract), so the design pairs a high standard with a hard stop. For code specifically, one evidence line supports chasing quality beyond "approved": across 39 proprietary codebases (30,737 files), low-quality code had 15 times more defects and 124% more development time per issue ([Tornhill and Borg](https://arxiv.org/abs/2203.04374); HIGH abstract, vendor metric so MEDIUM on independence), and a model of two public datasets found "amplified returns on investment in the upper end" ([Increasing, not Diminishing](https://arxiv.org/abs/2401.13407); HIGH abstract, vendor-adjacent data).

Why not certify absolutely? Agreement between GPT-4 and humans is 85% with ties excluded but 66% with ties counted ([Zheng et al.](https://arxiv.org/html/2306.05685); HIGH, tool-extracted), GPT-4o scored 50.86 on JudgeBench against a 50 random baseline while o3-mini (high) reached 80.86 ([JudgeBench](https://arxiv.org/html/2410.12784); HIGH, tool-extracted), and the Shankar study found "it is impossible to completely determine evaluation criteria prior to human judging of LLM outputs" ([Shankar et al.](https://arxiv.org/html/2404.12272); HIGH). Masters do not certify either. Valéry's saying comes from a March 1933 essay and concerns a work in general: "un ouvrage n'est jamais achevé … mais abandonné", with the "poem" wording added later ([Quote Investigator](https://quoteinvestigator.com/2019/03/01/abandon/); HIGH). Saint-Exupéry's sentence is hedged in French ("Il semble que la perfection soit atteinte…") and the popular designer version is a later paraphrase ([Hacker's Dictionary](https://lysator.liu.se/hackdict/split/elegant.html); MEDIUM). Hemingway's "thirty-nine times before I was satisfied" names a felt state, and the typescript read "before I got it right" ([Morgan Library](https://www.themorgan.org/blog/getting-question-right); MEDIUM-HIGH). The stopping tests with evidence behind them are a deletion test, an audit that nothing is arbitrary (Rams principle 8, [Vitsœ](https://vitsoe.com/gb/about/good-design); HIGH), parity with exemplars, "no named improvement survives confirmation", and a cap; "satisfied" is taste (craft note section 2; MEDIUM).

The definition the two notes support, merged and with the weakest links stated (design proposal; no study tested the combined procedure on an agent):

> A work is **perfect relative to bar Bn** when (1) every executable check for its type passes, with no regression against the pre-pass ledger and no failure on held-out checks the editing step did not see; (2) a deletion pass finds no element whose removal leaves the goal-relevant observables unchanged; (3) against at least two exemplars chosen before the pass, a blind, order-swapped, length-matched comparison by a judge that did not write the work rates it at or above the exemplar on every dimension that has a test; (4) a fresh-context reviewer asked to name improvements with a predicted observable effect produces none that an independent check confirms; and (5) the run stayed inside its cycle cap and lists its leftovers.

The limits are part of the definition. It is relative: exemplars cap the ceiling, and weak ones make "perfect" mediocre (craft note section 5; MEDIUM). Conditions 3 and 4 rest on LLM judgment, and "found no improvement" is not "none exists". The bar is Goodhart-prone, since shorter text can lose nuance and tests can pass trivially ([Strathern](https://www.Gwern.net/doc/statistics/decision/1997-strathern.pdf); MEDIUM). Taste dimensions (voice, delight, audience fit) are handled only by exemplar comparison and listed as leftovers. And it costs more than a review loop, which is why the cap exists.

## Incumbent-challenger loops gain only where an external evaluator decides

**Every loop that produced measured gains on strong starting points has a hardened evaluator.** FunSearch pairs an LLM with an automated evaluator that "guards against hallucinations and incorrect ideas" ([DeepMind blog](https://deepmind.google/discover/blog/funsearch-making-new-discoveries-in-mathematical-sciences-using-large-language-models/); HIGH, tool-extracted). AlphaEvolve found a 4x4 complex matrix multiplication with 48 scalar multiplications, the first improvement over Strassen in 56 years in that setting, using an evaluation cascade of test ensembles of increasing difficulty that filters faulty programs early, and it scores hard-to-code properties such as program simplicity with separate LLM calls inside the score dictionary ([arXiv 2506.13131](https://arxiv.org/abs/2506.13131); [HTML](https://arxiv.org/html/2506.13131v1); HIGH). Mind Evolution beats Best-of-N and Sequential Revision at constant inference cost and solves more than 98% of TravelPlanner and Natural Plan instances with a solution evaluator in the loop ([arXiv 2501.09891](https://arxiv.org/abs/2501.09891); HIGH abstract). Where the evaluator is another LLM or a weak proxy, the loop plateaus or is exploited: coverage rises log-linearly with samples (SWE-bench Lite from 15.9% to 56% at 250 samples) but without automatic verifiers majority voting and reward models plateau ([Large Language Monkeys](https://arxiv.org/abs/2407.21787); HIGH abstract), optimizing a proxy reward eventually lowers the gold score ([Gao et al.](https://arxiv.org/abs/2210.10760); HIGH abstract), and Sakana's CUDA kernel loop exploited its harness before the claims were walked back ([TechCrunch](https://techcrunch.com/?p=2969225), [EvoEngineer](https://arxiv.org/pdf/2510.03760); MEDIUM, search summaries).

**Sequential revision without a gate regresses, so the output must be the best state, not the last.** About 38% of correct answers were converted back to incorrect by a revision model under a naive approach, which is why Snell et al. choose the final answer by majority vote or verifier ([Snell et al.](https://arxiv.org/html/2408.03314); HIGH for direction, MEDIUM for the 38%). In Anthropic's frontend harness the author "regularly saw cases where I preferred a middle iteration over the last one", and complexity tended to rise across rounds ([Anthropic harness](https://www.anthropic.com/engineering/harness-design-long-running-apps); HIGH, author judgment). With vague prompts across 12 turns, Claude's coding pass rate under a "performance" prompt fell from 90% at turn 1 to near 0% by turn 4 and code length grew over 40 times ([Javaji et al.](https://arxiv.org/html/2509.06770); HIGH, tool-extracted). Self-Refine keeps the best-scoring output across iterations, not the last ([Self-Refine](https://ar5iv.labs.arxiv.org/html/2303.17651); HIGH). The only published incumbent/challenger scheme for subjective work is Autoreason: an unchanged incumbent A, an adversarial revision B and a synthesis AB are ranked blind by fresh judges, "Do nothing" is a first-class option, and the loop converges when A wins twice; it reports 77% against 73% single-pass for Sonnet 4.6 on 150 CodeContests problems, but "autoreason's held-out gains vanish" on Haiku 4.5 ([README](https://github.com/NousResearch/autoreason); LOW, unreviewed repository, tool-extracted). The README states no tie-breaking rule and does not say whether the two wins must be consecutive. An earlier-notes claim that ties go to the incumbent came from a secondary summary and is unsupported (`research_notes/AI post task bar raising skill/self_refinement_evidence.md:62`; LOW). Tie-keeps-incumbent is therefore adopted here as a design choice.

**The pass is worth its cost only at the edge of the model's ability.** The harness author found a solo run cost 20 minutes and $9 and produced a non-working core feature, against 6 hours and $200 for a playable result; "the evaluator is worth the cost when the task sits beyond what the current model does reliably solo", and on Opus 4.6 it became unnecessary for tasks the generator handled alone ([Anthropic harness](https://www.anthropic.com/engineering/harness-design-long-running-apps); HIGH). A good-to-perfect pass acts on results the model already did well, the regime where that author found the evaluator least valuable (LLM note section 1 inference; MEDIUM).

### Subtraction first is the best-supported opening move

LLMs share and exceed the human tendency to add. Across GPT-3.5 Turbo, Claude 3.5 Sonnet, Mistral, MathΣtral and Llama 3.1 the authors report "a clear preference for additive changes"; Mistral 7B lengthened summaries in 59.40% to 75.10% of cases when asked to improve text ([Santagata and De Nobili](https://arxiv.org/abs/2409.02569); HIGH abstract, preprint, small tasks). In four preregistered experiments (588 humans, 680 GPT-4 iterations) GPT-4 used additive strategies more when told to "improve" than to "edit" and kept adding when subtraction was more efficient ([Uhler et al.](https://arxiv.org/abs/2404.16692); HIGH abstract, GPT-4, puzzle tasks). Deletion is a weak skill in code: on 200 real-commit tasks whose required edit adds no code, deletion recall reached at most 71.7%, models found the right file for over 92% of deletions but the exact line under 52%, 29.0% of passing patches wrapped the target in a guard or fallback, and prompt changes alone moved success little ([CanItDelete](https://arxiv.org/abs/2607.28887); HIGH for the abstract-level claims, MEDIUM for the numbers; very recent, unreplicated). In a writing-agent study larger deletions correlated with higher user ratings and larger insertions with lower ones (both p<0.001), and Claude had the highest execution correctness but lower ratings because it inserted the most text ([Gooding et al.](https://arxiv.org/html/2503.19711v1); HIGH, tool-extracted, 2024-vintage models, correlation). Judges reward the same length: a repetitive-list attack fooled Claude-v1 and GPT-3.5 in 91.3% of 23 cases ([Zheng et al.](https://arxiv.org/html/2306.05685); HIGH). Human craft says the same without outcome data: Strunk's "no unnecessary words… no unnecessary parts" ([Gutenberg](https://www.gutenberg.org/files/37134/37134-h/37134-h.htm); HIGH), Rams's "as little design as possible" ([Vitsœ](https://vitsoe.com/gb/about/good-design); HIGH), and King's "2nd Draft = 1st Draft − 10%" ([NZIBS](https://blog.nzibs.co.nz/writing/ways-to-instantly-tighten-your-fiction/); MEDIUM), none with a controlled test that cutting improves artifacts. **No controlled experiment compares subtraction-first with addition-first refinement on human-judged quality**; the case is convergent and indirect (LLM note section 5; MEDIUM-HIGH for the inference that an unconstrained pass will grow the artifact).

## Judges cannot certify small gains without a protocol sized to close pairs

**The statistic that matters is accuracy on near-ties, and the evidence runs the wrong way.** Position consistency across swapped orders was 65.0% for GPT-4 and 23.8% for Claude-v1 ([Zheng et al.](https://arxiv.org/html/2306.05685); HIGH, 2023 judges). Across 15 judges, position bias is "strongly tied" to the quality gap, and similar-quality pairs are "difficult to judge, increasing the likelihood of position bias" ([Shi et al.](https://arxiv.org/html/2406.07791v9); HIGH qualitative, MEDIUM numeric; arXiv versions differ on judge count). With distractor features such as assertiveness, pairwise preferences flip in about 35% of cases against 9% for absolute scores ([Tripathi et al.](https://arxiv.org/abs/2504.14716); HIGH abstract, four open-weight judges). Judges favor LLM-written and low-perplexity text ([self-preference](https://arxiv.org/abs/2410.21819), HIGH abstract; [Laurito et al., PNAS 2025](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC12337326/), MEDIUM, search summary), and Anthropic's own evaluator "is still an LLM that is inclined to be generous towards LLM-generated outputs", with out-of-the-box Claude "a poor QA agent" until its logs were read and its prompt revised over several rounds ([Anthropic harness](https://www.anthropic.com/engineering/harness-design-long-running-apps); HIGH). Remedies exist for each bias. A panel of smaller judges from disjoint families beat a single GPT-4 judge with less intra-model bias at over seven times lower cost ([PoLL](https://arxiv.org/abs/2404.18796); HIGH abstract). Length control raised AlpacaEval's correlation with Chatbot Arena from 0.94 to 0.98 ([AlpacaEval LC](https://arxiv.org/abs/2404.04475); HIGH for the correlation). Benchmarks that separate close models need hundreds of prompts and confidence intervals, not single comparisons ([Arena-Hard-Auto](https://arxiv.org/abs/2406.11939); HIGH abstract). The tension is that Anthropic's multi-agent team found one LLM call with one prompt, scoring 0.0 to 1.0 plus pass/fail, most consistent and best aligned with humans, while still needing human testers to catch what automated evals missed ([Anthropic multi-agent system](https://www.anthropic.com/engineering/multi-agent-research-system); HIGH). That result concerns decomposing one rubric into many judges, not polling several families on one question (LLM note section 2 inference; MEDIUM).

The notes therefore justify, but did not test, a combined protocol for small improvements: both orders with an inconsistent verdict counted as a tie, at least two judge families or a fresh-context reasoning judge, a pairwise verdict that must agree with pointwise per-item verdicts, and length normalization (LLM note section 2; MEDIUM, components HIGH, combination untested). Because judges are generous to LLM output, "the judge preferred it" is weaker evidence here than in a defect-catching pass, and objective checks plus human-calibrated exemplars should carry the weight (LLM note section 2; MEDIUM-HIGH). An agent's own sense of improvement does not count either: readers in a reading-aloud study could not tell the method helped ([Learning Scientists](https://learningscientists.org/blog/2022/10/20-1); MEDIUM, summary).

## The bar must rise by contrast but stay anchored to the user's words

References and contrast sharpen judging. Math-grading failures fell from 14 of 20 with the default prompt to 6 of 20 with chain of thought and 3 of 20 reference-guided ([Zheng et al.](https://arxiv.org/html/2306.05685); HIGH, tiny sample). Rubrics built by comparing preferred and rejected responses, split into hard rules and principles and pruned to items that preserve preference labels, lifted a reward model 8.4% over size-matched baselines ([OpenRubrics](https://arxiv.org/abs/2510.07743); HIGH abstract). Fixed rubrics "can lose their effectiveness over time and open the door to reward hacking", and a memory bank of items scored by how well they separate reference from candidate answers, paired with adversarial candidates that surface new dimensions, produced more discriminative rubrics ([SibylSense](https://arxiv.org/abs/2602.20751); HIGH abstract, RL setting). Explicit rubrics help humans too (g=0.45, k=21; the reported interval [0.312, 0.831] does not center on 0.45 and should be checked in the paper) ([Panadero et al. 2023](https://deustoteka.deusto.es/items/59022074-df96-4c6a-8c52-3aa513c0ae3e/full); HIGH abstract). Comparing two cases made students "nearly three times" as likely to apply a strategy ([Kellogg record](https://www.kellogg.northwestern.edu/academics-research/research/detail/1999/analogical-encoding-facilitates-knowledge-transfer-in-negotiation/); MEDIUM; learning transfer, not artifact quality). Mastering engineers level-match references because a 1 dB difference can make a version "win" regardless of quality ([PureMix](https://www.puremix.com/blog/how-to-use-reference-tracks-when-mixing); MEDIUM, vendor).

Three cautions bound the escalation. Judges can ignore a reference that conflicts with their own knowledge, and the failure survives prompt-based mitigations ([Lee et al. 2026](https://arxiv.org/abs/2601.07506); HIGH abstract, QA setting). Criteria drift both ways: new criteria are added after seeing outputs, and existing criteria are reinterpreted to fit the model's behavior ([Shankar](https://arxiv.org/html/2404.12272); HIGH), so a self-generated bar with no anchor can wander (design inference, MEDIUM). Criteria wording steers output: phrases like "museum quality" drove visual convergence, and the harness author weighted design quality and originality above craft and functionality because Claude already did the latter well ([Anthropic harness](https://www.anthropic.com/engineering/harness-design-long-running-apps); HIGH, qualitative). The exemplar-contrast mechanism itself is an extrapolation: no study gave a critic best-in-class exemplars and measured critique specificity (LLM note section 3; MEDIUM-LOW). Exemplar sourcing without the web or user input is unresolved in the notes, so section (a) below makes a design decision.

## Polishing strong work has measured harms that the gate must price in

LLM rewriting flattens style: across 3 studies, 7 datasets and over 880,000 texts it preserved content while cutting writing-complexity variance by 21-50% ([Sourati et al.](https://arxiv.org/abs/2502.11266); HIGH abstract; the venue year is unresolved, 2025 versus 2026). Models told to make only grammar edits still changed meaning significantly ([Abdulhai et al.](https://arxiv.org/abs/2603.18161); HIGH abstract), and humans make self-contained, meaning-preserving edits while LLMs scatter edits that shift meaning; sentence-level edits accepted or rejected independently performed better in human evaluation ([Ziegenbein et al.](https://arxiv.org/abs/2604.12770); HIGH abstract). Optimizing one axis costs another: critique-revision raised harmlessness monotonically over four revisions while pure helpfulness fell and preference-model scores became less calibrated at higher values ([Constitutional AI](https://arxiv.org/html/2212.08073); HIGH, tool-extracted), and under vague iteration feasibility fell from 5 to 1 by turn 3 while originality rose from 6 to 9 in one reported table ([Javaji et al.](https://arxiv.org/html/2509.06770); HIGH, tool-extracted, single example). Same-model evaluator ratings rise while human-judged quality stalls or falls ([Pan et al.](https://arxiv.org/abs/2407.04549); HIGH abstract), and failed attempts left in context cut performance 10-20% across 11 models and 8 tasks ([Contextual Drag](https://arxiv.org/abs/2602.04288); HIGH abstract, preprint). Nobody measured "lifeless polish" directly (craft note section 4 gap), and whether one polish of an already-excellent, voice-rich piece loses as much as the corpus-level studies is unmeasured (LLM note section 4; MEDIUM). The risk is concrete enough to require explicit voice-and-meaning invariants and per-axis acceptance. A counter-hazard stands from the earlier work: Opus 5's guide says explicit verification instructions "cause over-verification" and sample cost-control text says "do not use subagents to verify or double-check your own work" ([Opus 5 guide](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5); HIGH), so every judge call here must be bounded, evidence-producing and capped.

Craft slogans supply structure, not evidence. Plussing, the Braintrust, marginal gains, cut-10%, kaizen/kaikaku and Collins's "good is the enemy of great" have no controlled outcome evidence; Wiggins called marginal gains "a load of rubbish" ([ITV](https://www.itv.com/news/update/2017-03-27/wiggins-brailsfords-marginal-gains-a-load-of-rubbish/); MEDIUM), James Clear's fact-check offers no causal evidence ([James Clear](https://jamesclear.com/atomic-habits/cycling); HIGH), and Rosenzweig's critique shows the Collins selection cannot separate cause from effect ([Wharton](https://knowledge.wharton.upenn.edu/article/the-halo-effect-debunking-some-hot-business-books-with-one-of-his-own/); MEDIUM). The design uses them only as constraints: plussing becomes "each change states what strength it preserves and what it adds", marginal gains becomes decomposition into measurable dimensions, and kaizen/kaikaku becomes the rule to surface a rewrite instead of silently doing it ([Fabrico](https://www.fabrico.io/blog/kaizen-vs-kaikaku/); MEDIUM; consistent with `/Users/firegroup/.paseo/seat-homes/seat-21d4b2b72b56/CLAUDE.md:21`, "Propose before executing").

## Where sources conflict or are weak

**"Better, not perfect" versus "perfectize".** The repo rule (`aio-code-review/SKILL.md:54`), Google's standard and the earlier seed reject perfection as a target; the user's definition asks for it. Both new notes reconcile them by scope (approval versus post-approval search) and by redefining perfect as relative and finite. That is a design reading (MEDIUM), not a vendor statement, and it needs the user's confirmation. The residual disagreement is real: a fixed-point report on a strong artifact often reads "no change", which a user expecting visible improvement may call a failure.

**Stopping thresholds disagree and are all unsourced.** The earlier report ended at one clean pass; the LLM note says default two cycles, hard stop at three, early stop after two consecutive empty cycles; the craft note says two consecutive passes with no verified improvement. The only external anchor is Autoreason's k=2, whose README does not say "consecutive" ([README](https://github.com/NousResearch/autoreason); LOW), plus Self-Refine and CRITIC curves showing most gain in 2-3 rounds (HIGH for the curves, MEDIUM for any number). Section (e) picks two consecutive empty cycles with the second at an escalated bar, and flags it as a design proposal.

**One holistic judge versus many judges.** Anthropic's multi-agent team preferred a single holistic call ([Anthropic](https://www.anthropic.com/engineering/multi-agent-research-system); HIGH); PoLL and Shi et al. favor panels. The reconciliation (decomposition versus polling) is an inference (MEDIUM). Pairwise versus pointwise conflicts similarly: pairwise is more distractor-prone (35% versus 9% flips) but better for relative taste, so the protocol requires agreement.

**Fresh-context judging versus the Opus 5 cost warning.** The Opus 5 guide discourages verification instructions and verify-by-subagent for ordinary work (HIGH), while Claude Code guidance recommends a fresh-context reviewer (HIGH). The earlier report read these as unbounded "verify again" prose versus bounded, evidence-producing checks (MEDIUM, untested); that reading carries over.

**Family diversity may not be available.** A marketplace user may only have same-family subagents, in which case the family requirement reduces to fresh context plus reasoning-mode judging, which is weaker (LLM note section 6 gap). Different Claude model tiers are still one lineage, and no source tests whether tiers count as separate families (design inference, LOW-MEDIUM).

**Weak or dated evidence the design inherits.** The Autoreason numbers are LOW (unreviewed repository, mixed held-out result, gains vanish at 60% private-test accuracy on Haiku 4.5, a 59-70% word-count drop on Haiku 3.5). The addition-bias studies use GPT-4, GPT-3.5 and 2024-vintage models; only Javaji et al. and CanItDelete reach newer Claude models, and CanItDelete is a very recent unreplicated preprint whose tool extraction named a model the note author could not verify. The Snell 38% figure is MEDIUM. The Sakana, Laurito and Shi-numeric items are search-summary level. The Sourati venue year is unresolved. Craft sources include vendor material (mastering, CodeScene), lecture-note secondary sources (Tufte), blog summaries (Rumelt, Ousterhout) and unverified quotes: the origin of plussing conflicts between Disney and *Roger Rabbit* sources, and the Pixar origin story conflicts between Toy Story and Toy Story 2 (MEDIUM, unresolved). No peer-reviewed study measures overworked art, a quality-versus-pass-count curve, time-gap proofreading, or exemplar-conditioned critique. **None of the proposed rules has been tested end to end as a Claude Code skill**, and every threshold below is a design proposal.

## Design implications

### (a) The rising bar has a frozen core and a versioned, exemplar-derived escalation layer

The bar is written before the first edit and logged at every version. The **frozen core** holds the user's requirements quoted verbatim, declared project standards, the artifact's purpose and audience, and four invariants (author voice, meaning, public interface, scope). Precedence stays as in the seed: declared standards, frozen contract, requirements, then the skill's own lens ([seed persona L18-L23](https://github.com/robisson/build-like-amazon-agent-skills/blob/1d2e59d5f05ee8c08a64678e9198b229db694394/agents/code-review-bar-raiser.md#L18-L23); HIGH for the text, MEDIUM that the order suits a general skill). No escalated item may override or relax the core; a conflicting item is dropped and logged. The core exists because static rubrics decay and drift ([SibylSense](https://arxiv.org/abs/2602.20751), [Shankar](https://arxiv.org/html/2404.12272); HIGH) and a self-generated rising bar has no stable anchor without one (design inference, MEDIUM).

The **escalation layer** starts empty. Before judging the draft, the skill fixes at least two exemplars (design proposal; the craft note's definition says N≥2 and mastering practice uses two or three). Sourcing order (design proposal, resolving the craft note's open item): exemplars the user names; artifacts the project already treats as its standard; canonical external works fetched with the URL logged; canonical works recalled from the model's own knowledge and flagged as parametric; and if none, the report states that the ceiling is the incumbent and the bar rises only through objective checks. A self-generated exemplar is the weakest case because the judge may rate by its own taste (LLM note section 3; MEDIUM). Exemplars must come from outside the draft and be matched in scope, length and format before comparing. For each dimension the skill writes the observable gap between incumbent and exemplar as a candidate rubric item, and keeps it only if it separates the two. Each cycle increments the version and logs the item, its source (exemplar contrast, failed challenger, or improvement probe), its test and its cycle. Weight dimensions with headroom, as the harness author did. Items may be retired only for conflicting with the core or failing the separation test, with the reason logged (design proposal; this amends the earlier "never loses an item" ratchet, which had no empirical test). The original request is re-read at each cycle boundary to anchor against Goodhart drift.

### (b) The pass starts with a deletion test and treats every edit as a challenger

| Step | Action | Basis |
|---|---|---|
| 0. Means check | Record which means exist: executable checks, exemplars, independent judges. With no checks, no exemplar and only same-family judges, the pass narrows to the deletion test and invariant-preserving cuts and says so | Harness cost and "beyond what the model does reliably solo" ([Anthropic](https://www.anthropic.com/engineering/harness-design-long-running-apps); HIGH); judge ceilings (HIGH) |
| 1. | 2. Deletion test | List every element (code: function, parameter, branch, comment, dependency; prose: paragraph, sentence, hedge; plan: step; analysis: claim, section; UI: component, state, color). ### (c) The acceptance rule makes the incumbent win ties, as a labeled design choice

A candidate edit is accepted only if it clears these gates in order, and any failure rejects it with the reason logged. First, the **objective cascade**: build, type check and lint, then existing tests, then held-out checks the editing step did not see, then measurements (size, benchmark, coverage, accessibility audit, link check, recomputed numbers). Every ledger check must still pass, and any targeted measurable axis must improve or hold; a judge cannot overrule a failed check ([FunSearch](https://deepmind.google/discover/blog/funsearch-making-new-discoveries-in-mathematical-sciences-using-large-language-models/), [AlphaEvolve](https://arxiv.org/html/2506.13131v1), [Gao](https://arxiv.org/abs/2210.10760); HIGH for objective-first, MEDIUM for the held-out requirement). Second, the **invariant check**: voice, meaning, public interface and scope are compared by something the judge did not write (an interface diff, a claims-list diff, a fresh reader's answers to preset questions) ([Sourati](https://arxiv.org/abs/2502.11266), [Abdulhai](https://arxiv.org/abs/2603.18161); HIGH abstracts; check design is MEDIUM). Third, **per-axis acceptance**: no non-targeted axis may regress, and any trade is reported ([Constitutional AI](https://arxiv.org/html/2212.08073), [Javaji](https://arxiv.org/html/2509.06770); MEDIUM-HIGH). Fourth, for axes with no objective check, the **judge protocol**: pairwise in both orders with an inconsistent verdict counted as a tie, plus pointwise per-item verdicts that must agree, at least two judge families or a fresh-context reasoning judge, length normalized, and the author never the judge (components HIGH, combination untested, MEDIUM). Fifth, the **tie rule**: a tie, an order-inconsistent verdict, or a disagreement between pairwise and pointwise keeps the incumbent. This is a design choice, justified by an asymmetry of costs: a false accept can flip a correct result, flatten style or shift meaning, while a false reject costs one line in the leftovers list (inference from Snell, Sourati and Gooding; MEDIUM-LOW). Sixth, **additions** face a stricter gate: a named gap against the rubric, an objective check or an exemplar contrast, and a size budget under which net size may not grow in a cycle unless the addition cites a failing dimension with objective evidence (design proposal, falsified if budgets reduce quality on tasks that genuinely need more content).

Before trusting a judge on a subjective axis, the skill seeds a **resolution check** from the artifact itself: a deliberately degraded copy of the incumbent that the judge must rank below it in both orders. A judge that fails cannot certify a subtle improvement, and that axis is reported as "not verifiable at this resolution" with no change accepted on it. Passing is necessary and not sufficient, since a judge that detects a gross degradation may still fail on a close pair (my caveat). This is among the least-supported rules (LLM note section 6, rule 4; MEDIUM). Skip it when every axis has an objective check.

### (e) Stopping is a fixed point, a cap, or an honest escalation, and the leftovers list is mandatory

The rules compose and the first to fire ends the run. **CONVERGED:** two consecutive empty cycles (no deletion candidate and no challenger accepted), the second run at an escalated bar and including the name-an-improvement probe, whose items must each predict an observable effect and pass independent confirmation; the probe is the guard against manufactured findings (CodeRabbit's 56.3% rejection rate; HIGH). The earlier report declined this rule because passes were capped at three and an empty pass met a closed bar; here an empty cycle proves little on its own because the bar can always be raised, so the second empty cycle at the escalated bar is the fixed-point test (design proposal; Autoreason k=2 is LOW and unclear on "consecutive"; the craft note's threshold is unsourced). **CAP REACHED:** hard stop after three cycles (design proposal anchored to Self-Refine and CRITIC curves, HIGH for the curves and MEDIUM for the number, and not measured for Claude Code); the user may raise it; the report says "not converged" if cycle three still accepted a change. **ESCALATED:** stop on an axis when the judge fails the resolution check or the remaining differences are taste-level, and stop the run when the best remaining improvement is rewrite-sized (touches the frozen core, the public interface or most of the artifact), which is surfaced with options and not executed, following the kaizen/kaikaku distinction and the user's propose-before-executing rule. **Restart, not append:** after a rejected cycle that polluted the context, restart from the incumbent plus logged findings in a clean context ([Contextual Drag](https://arxiv.org/abs/2602.04288); HIGH abstract). **Never on self-score:** no continuing or stopping on the model's own number or "looks perfect" ([Pan](https://arxiv.org/abs/2407.04549), [Xu](https://arxiv.org/abs/2402.11436); HIGH abstracts). **Infeasibility escape:** if a check or requirement is wrong, report it instead of working around it (earlier report, citing Anthropic's anti-hack prompt; HIGH).

The closing block is a fixed-point report and never says "perfect": "Released at rubric vN under checks C. K challengers tried, M accepted, J rejected (reasons). Independence level L; judge families used; resolution check result. Leftovers." The **leftovers list** carries rejected challengers with reasons, taste-level items that cannot be verified, deferred rewrites, out-of-scope ideas, axes not verifiable at this resolution, checks that were unavailable, and the exemplars used with their sources. Its purpose is to turn "I could not verify this" into a legal output.

### (h) The revised RED plan adds a strong starting artifact, a no-op control and over-polish metrics

The mechanics stand: RED is the no-skill control only, run on two model tiers (one earlier-generation, one current Opus-class, because the addition-bias studies use older models and Opus 5 over-verifies when told to verify, per its [prompting guide](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5); HIGH), 5 reps per cell, a fresh context and clean repository per rep, and the rule that the control must show the target failure in at least 3 of 5 reps on at least 3 of the 5 scenarios on at least one tier or the project stops (writing-skills `SKILL.md:582`; HIGH per the earlier report). The control prompt is what the user will type, "make this perfect". Target failures, any one of which counts: a previously passing check fails; net size grows without a cited failing dimension; a blind check finds a meaning or voice shift; an absolute "perfect" claim; and, on the no-op scenario, any non-trivial change. If the unaided model already returns the no-op artifact unchanged in at least 4 of 5 reps on both tiers, the over-polish motivation is unproven on that scenario. All scenarios are design proposals (LOW-MEDIUM).

| ID | Strong starting artifact | Headroom available | Primary graders |
|---|---|---|---|
| P1 | Correct, tested code module, 150-300 lines | Removable dead or duplicated code; one benchmarked improvement | Held-out tests, benchmark, net size ratio, regressions, guard-and-go count, accepted-edit precision |
| P2 (no-op control) | Unit from a mature, heavily reviewed codebase, chosen by a human before the run | None expected; a human panel blind to arms sets "unchanged is right" | Any diff, diff size, new abstractions or files, cycle count; limit: tests restraint relative to a human reference, not absolute perfection |
| P3 | Strong human-written prose with voice, 600-1,000 words | Light cuts only | Blind human preference against the original in both orders, preset-question answers unchanged, blind voice fidelity, words added, hedges added |
| P4 | Plan or analysis that meets its brief but lacks rival explanations, confidence labels or an orphan-step cut | Gaps checkable by the (d) tests | Planted gaps closed, new claims checked against data, net length, unsupported claims added |
| P5 | Polished UI component or page | Token drift, one failing accessibility item | Automated audit, token-compliance count, task completion by a fresh agent, blind side-by-side, components or states added |
| P6 (judge calibration, not an agent run) | Pairs per artifact type: incumbent against subtly degraded copy; incumbent against a human-authored better variant | n/a | Separation rate in both orders for single-judge single-order versus the (c) protocol; inconsistent-as-tie rate |

## Conclusion

The new evidence changes what the skill is. The earlier skill was a detector; this one is a governor on a process whose unaided default is documented to add, bloat and drift. No study shows that "make it perfect" helps strong work. The studies show that unaided models add, judges reward length, sequential revision flips correct answers, rewriting flattens voice, and loops improve only where something external decides what survives. So the skill's value lies mostly in refusing changes (design inference, MEDIUM): a deletion-first opening, a gate in which the incumbent wins ties, a bar that cannot drift from the user's words, and a report that lists what could not be verified. The word "perfect" survives only as a relative, logged and reproducible claim.

The unresolved center is the judge. Nothing in the notes measures how well any LLM judge separates two already-good subjective outputs, and the protocol that compensates (both orders, several families, pointwise plus pairwise, length control, a seeded resolution check) has never been run together. That is why the cheapest next step is the RED test with the no-op control rather than the skill. If the unaided model already leaves an excellent artifact alone and does not bloat strong ones, the project ends there, and that outcome is as informative as a pass.
